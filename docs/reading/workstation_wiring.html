01

The whole surface, in one picture

The workstation is a single React bundle served as static files by the same FastAPI process that serves the API. There is no separate dev server in play, no second origin, and no direct connection to anything else — no database, no Redis, no telephony. The browser has exactly two live channels to exactly one host.

02

Who owns what

This is the table to audit against. The client's stated rule is the server owns state, the client owns presentation — so every row in amber is a deliberate exception, and every deliberate exception is a place the two can disagree.

The blue rows all arrive inside one object, Snapshot, returned by GET /v1/agent/me and by every mutating request. There is no partial update path and no client-side derivation of them.

04

The socket, and what it actually does

The interesting thing about the WebSocket is how little it carries. Four push types exist, and the client acts on the content of exactly one of them. Everything else is a doorbell: something changed, go and re-read.

The ordering contract

Each agent has their own sequence counter and a 200-message outbox on the server, and a message is written to the outbox before delivery is attempted — a message that failed to send is precisely the one a reconnecting client needs replayed. On reconnect the client sends the highest seq it applied; the server replays exactly the gap, then sends a fresh snapshot on top. Anything at or below what the client already applied is dropped, because a duplicate offer is a call ringing at a desk that already declined it.

06

Where the logic lapsed — all fixed

Found by reading the client against the server and confirming each on the running system. All of them have since been fixed — kept here because the pattern is the lesson: every one was the client holding, deriving, or guessing something the server already knew (D68). None of them was the disclosure gate; that one holds.

fixed · B7An ignored offer stranded the agent for the shift

The worst of them, and it was not in the client at all. Nothing in the running process ever called expire_offers, dispatch.tick, or presence.sweep — all three written, all correct, all wired to nothing. expire_offers even documents itself as running "on a timer in the API process"; there was no timer.

So an ignored offer never resolved: the agent sat in OFFERING with no card and no way out, and the caller was never re-matched. It survived P2b because the visible half was correct — the card hides itself at zero on purpose, so the client was counting down a deadline nobody enforced.

ignoring the offer for 25s (timeout 20s, sweeper every 1s) offer None system_state available ← was stuck on "offering", forever agent_intent not_ready intent_reason rona_missed_offer

The lesson, now in NEXT_SESSION: anything that must happen because time passed needs a test in which only time passes. Every existing test drove the system through endpoints, and endpoints tick the dispatcher on the way through — so the suite proved the ticking worked without proving anything caused it.

fixed · D68Saving the wrap-up showed no confirmation

The "saved" badge is keyed on savedCalls.has(callId) — but saving the record moves the call to CLOSED, and active_call_session_id only reports calls that are IN_CALL or WRAP_UP. So the moment the save succeeds, callId becomes null, the lookup becomes savedCalls.has(""), and the badge never renders. The form unmounts at the same instant, so the agent presses Save and gets nothing back at all.

clicked: บันทึก after_active_call_id: null acwBarStillThere: true ← correct, D45 holds savedBadgeShown: false ← should be true wrapupPanelStillThere: false

The deeper cause is that the server knows whether a wrap-up was saved and does not say so. It is stored in container.wrapups[call_session_id] and never surfaced in the Snapshot, which forced the client to track it locally. A refresh during ACW loses it too. Fix: put it in the Snapshot and delete savedCalls.

fixed · D68Every timer trusted the laptop's clock

Timers are computed as Date.now() − Date.parse(server_timestamp). That fixed the refresh bug, but it silently introduced a dependency on the browser clock agreeing with the server's. The Snapshot already carries server_time for exactly this — and nothing reads it:

$ grep -rn "server_time" apps/workstation/src/ api.ts:133: server_time: string | null; ← declared, never used

On one machine this is invisible. On a demo laptop whose clock drifted, or a second machine in a different timezone with a bad NTP sync, the call timer is wrong by the offset and nobody would suspect the clock. Fix: compute an offset once per snapshot and add it in elapsedSince.

fixed · D68The client second-guessed a server threshold

App.tsx:147 const longAcw = presence.long_acw || (acwSeconds !== null && acwSeconds >= 45); config.py:181 acw_long_after_s: float = 45.0

The server already computes long_acw from configuration, and the client ORs it with its own hardcoded copy of the same number. Tune acw_long_after_s — which Q9 explicitly expects to happen, since these thresholds are guesses — and the screen keeps warning at 45 seconds while the server has moved on. It also contradicts the panel's own stated rule that nothing here decides what may be shown. Fix: delete the client half.

still openThe challenge list exists twice

CHALLENGES in panels.tsx and NAMED_CHALLENGES in attestation.py are two hand-maintained copies of the same list, and the server rejects anything not in its copy. Q12 says this list is unconfirmed and will change once Krungsri weighs in — so the drift is scheduled, not hypothetical. The same pattern repeats in the four label maps (INTENT_LABEL, SYSTEM_LABEL, ASSURANCE_LABEL, URGENCY_LABEL): add an enum value server-side and the screen shows a raw code. Fix: serve the list, the same way the app and the IVR share one menus.yaml.

design noteEvery push costs a full snapshot

Three of four socket messages call quietRefresh(), so N pushes cost N complete GET /me round trips — each one re-rendering the brief, the queues and the presence block. Correct and simple at one agent with one call. At fifteen agents on a busy floor it is a thundering-herd shape, and the payload already contains everything needed to patch in place. Not a bug today; a thing to measure before it is one.

design noteThe whole tree re-renders four times a second

useSecondTicker fires every 250 ms and lives in App, so every panel re-renders 4×/second for as long as an agent is signed in — even with no call, no timer on screen, and nothing changing. It is also why the old busy flicker was so visible. Fix, if it ever matters: move the ticker into the two components that display a timer.

partly fixedTwo unused endpoints (the dead ref is gone)

POST /captures/{id}/label and GET /agent/queues are routed and reachable but no client calls them. previousState in App.tsx is written on every state change and never read. Harmless, but each one is a small false signal about what the system does.

gapThe wrap-up draft is not persisted anywhere

disposition, notes and followUp live only in the component. A refresh mid-ACW — or a crash, or a closed laptop — loses whatever the agent typed. D45 anticipates the shape ("drafts are per-call and persist"), so this is an unbuilt piece rather than a wrong one, but today the words are gone.

07

What holds

Worth stating as plainly as the faults, because these are the parts that would be expensive to get wrong and are not wrong:

  • The gate is structural, and it moved rather than went away. D74 opened display to the agent from L1 — showing a bank employee the record they were routed is internal processing, not disclosure — and gates what the agent may say and do instead. The mechanism is unchanged: BriefOut still cannot carry the raw snapshot, and L0 carries nothing, which is where the byte-level regression test now points.
  • No identity is ever asserted by the client. No request carries an agent_id; it comes from a cookie the JavaScript cannot read.
  • Permission is never computed on this side. offerable and declarable arrive as answers, so the screen and the matcher cannot disagree about who is available.
  • The socket is not authoritative. Drop it and offers still exist, still time out, still re-match. The tab is a view.
  • One writer for the digits. The optimistic append that invented an eleventh digit is gone; the panel renders only what the server sent.
